LawVM

Bounded verification map

Different tools establish different properties.

LawVM combines CI checks, runtime contracts, generated tests, bounded model proofs, experimental independent checking, and case-specific external review. The combination is useful only when each conclusion stays inside its mechanism and scope.

The important model boundary

The executable mirror is stronger evidence about the current selector than the stale model alone.

bounded model

Z3

SMT proofs establish named propositions for deliberately encoded finite models. Their assumptions and mapping to production code remain separate review objects.

structurally stale

TLA+

The temporal-overlay source model preserves useful invariant vocabulary, but it lacks later expiry and tombstone behavior. A regime-handoff rule also required a carve-out absent from the original invariant.

real code in CI

Hypothesis mirrors

Generated tests call the actual selector for selected invariants, so implementation drift can fail CI. They still cover declared properties rather than all legal-time semantics.

Explicit non-claims

LawVM is not formally verified end to end.

No complete refinement

There is no formal map proving the TLA+ or Z3 abstractions refine to the production Python implementation.

No complete amendment semantics

There is no general formal semantics or independent entailment checker for arbitrary legislative prose.

No universal enforcement

Mutation observation, receipts, admission, and blocking differ by frontend, family, profile, and lane.

No external system audit

No independent party has audited the complete implementation, source universe, evidence plane, and release process.
